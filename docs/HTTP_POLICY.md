# Public-source fetching policy

The project fetcher retains bounded retries, explicit HTTP status handling, public-URL validation, per-host pacing, cache and content-size limits. Authentication failures, 403s, unreadable responses, unavailable robots policies and cross-origin robots redirects stop automatic retrieval. They are recorded with exact causes; they are not all labelled publisher denials.

Robots path matching uses locked `protego` 0.7.x, whose [documented parser](https://github.com/scrapy/protego) implements the matching rules of [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html). More-specific matching paths control; equally specific allow/disallow rules prefer allow. Matching handles group selection/merging, wildcards, end anchors and encoded paths. This corrects Python 3.11's first-match behavior, which incorrectly blocked an explicitly allowed public viewer beneath a root denial. It also prevents a broad earlier allow from hiding a more-specific denial. No host-specific exception is used.

The fetcher, not the parser library, controls network requests, redirects and status handling. Conservative failures remain in place. Crawl-delay and Request-rate both contribute to minimum spacing. Published visit windows require separate scheduling and are not silently ignored. Intervals above the configured maximum (at most 300 seconds) defer retrieval; permitted long waits occur in chunks of at most 30 seconds. HTTP Retry-After above 60 seconds also defers the source.

Synthetic transport tests verify both rule orders, specific denials, allow ties, exact/wildcard paths, Unicode/percent encoding, agent-group merging, request-rate spacing and visit-window deferral. Existing tests cover robots errors, long delays, private/credential URLs, redirects, source failures and cache behavior. These checks precede any newly permitted source request. Public-viewer availability does not authorize a protected underlying endpoint, bypass a login, or establish permission to redistribute raw documents.
